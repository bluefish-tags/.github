# Bluefish - Edit Pages You Are Allowed to Write

At a glance:
- A project of HTML and text files you created
- Tags and a preview of what you typed
- Encoding visible before a risky save
- A local folder, not a copied site

## The File You Are Writing

Bluefish is an editor for markup and code you author. You open a file from a directory you can explain, change a heading or a link, and save. The browser then shows that file. If the browser shows a different page, you saved somewhere else or you are previewing another path.

A project is a list of those files. It is not a mirror of someone else's server. Do not paste a commercial page into the editor and treat the result as yours. A template you may use is a starting point you save under your own name.

## Tags You Typed

Highlighting follows the tags you wrote. A broken tag is a line you can read, not a reason to import a whole site to hide the error. Fix the line, save, and reload the local file. Images in the page have to be images you may use, stored where the path says they are.

Remote upload, if you use it, is to a host you administer or were given. Check the host. If the login fails, stop. Do not try other accounts, and do not store the password on a shared Windows login.

## A Local Preview

Preview against the file you just saved. A missing picture is a wrong path. Put the image back beside the page. Do not hotlink a file you do not have rights to embed. The preview is a check, not a publisher.

Keep the source after you upload or export. The next sentence change happens in Bluefish, then you save again. A screenshot of the browser is not the source.

## What You Do Not Publish

Do not publish passwords, customer lists, or a private path in a page you are about to upload. Do not edit files under the Windows directory to test a tag. Close the project on a shared PC so the next person does not see the drafts.

## Encoding And Save

Read the encoding before you save a file that already contains letters you need. A wrong save can replace those letters. If you are unsure, copy the file first, save the copy, and open it in a browser. The original stays until the copy looks right.

## A Folder You Can Find

Put the project in a directory you will recognize after a restart, not in a temporary download folder. Copy that folder when the pages matter. Bluefish is not the archive. The files are.

## Installation Path

| Step | Action |
|---|---|
| 1 | Install Bluefish and create a project in a folder you own |
| 2 | Add one HTML file you are writing and type a heading |
| 3 | Save, then open that file in a browser |
| 4 | Fix a missing image path before you add more pages |
| 5 | Upload only to a host you may use, and keep the source |

## Player Profile

Bluefish fits someone writing their own pages or maintaining a site they were asked to edit. It does not fit grabbing a website you do not own, a shared PC with stored passwords, or a save that rewrites encoding on the only copy.

## Help Desk

The browser shows an old page? You opened the wrong path or did not save. Save and reload the file you edited.
Letters turned into marks? Restore the copy and check the encoding before the next save.
A picture is missing? The path is wrong. Put the file back. Do not pull it from a site you may not use.
Upload failed? The host or the user is wrong. Stop.
You wanted a full copied website? That is not this job. Write the pages you are allowed to publish.

## Reader Notes

Work on one folder and one heading until the browser matches the file. That habit matters more than a large template. The project list is only a convenience. The backup is a copy of the directory.

Remote features do not change who owns the server. A failed login is the end of the attempt. Do not keep credentials in a project you leave on a shared desk.

When the page is ready, keep the source beside any copy you uploaded. The next edit is a text change, then a save, then a reload. A screenshot will not let you fix a sentence.
